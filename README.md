# Marking AIS – MVP

Автоматизированная информационная система для управления маркировкой и оборотом учебников.

Проект предназначен для создания лёгкой MVP-версии AIS, в которой можно создавать карточки учебников, формировать коды маркировки, проводить операции с кодами, контролировать их статус и проверять DataMatrix через отдельный веб-сканер.

## Что представляет собой сервис

Marking AIS состоит из двух пользовательских частей:

1. **AIS – основная информационная система**
   - управление участниками;
   - пользователи и роли;
   - карточки учебников;
   - GTIN;
   - коды маркировки;
   - заказы кодов;
   - операции с кодами;
   - документы;
   - история операций;
   - финансовый баланс и Billing;
   - Dashboard.

2. **Текшер – сервис публичной проверки DataMatrix**
   - работает как отдельное React-приложение;
   - сканирует DataMatrix камерой смартфона;
   - поддерживает сканирование фотографии;
   - разбирает GS1 DataMatrix;
   - получает GTIN и серийный номер;
   - обращается к AIS за информацией о коде;
   - показывает сведения об учебнике, владельце и истории;
   - автоматически обновляет статус уже проверенного кода.

## Коды маркировки

Для каждого кода хранятся:

- идентификатор;
- GTIN;
- серийный номер;
- GS1 Payload;
- DataMatrix;
- владелец;
- учебник;
- статус;
- дата создания;
- дата последнего изменения.

Жизненный цикл кода:

`EMITTED → APPLIED → IN_CIRCULATION → WITHDRAWN`

Где:

- **EMITTED** – код выпущен;
- **APPLIED** – код нанесён;
- **IN_CIRCULATION** – код введён в оборот;
- **WITHDRAWN** – код выведен из оборота.

Серийные номера генерируются автоматически с проверкой уникальности.

DataMatrix генерируется в формате ECC200.

> В текущем MVP локально сгенерированный DataMatrix является тестовым кодом AIS и не является официальным государственным кодом маркировки.

## Заказы кодов

AIS позволяет создать заказ на необходимое количество кодов для выбранного учебника.

Процесс заказа:

`Calculate → Reserve → Generate → Capture`

При ошибке используется:

`Release`

Стоимость в текущем MVP рассчитывается по количеству кодов.

---

## Billing

Billing реализован как отдельный внутренний слой AIS.

Поддерживаются:

- расчёт стоимости;
- резервирование средств;
- списание;
- освобождение резерва;
- возврат средств;
- баланс;
- зарезервированная сумма;
- доступный остаток.

Основные API:

`POST /api/billing/calculate`

`POST /api/billing/reserve`

`POST /api/billing/{id}/capture`

`POST /api/billing/{id}/release`

`POST /api/billing/{id}/refund`

`GET /api/billing/balance/{participantId}`

## Операции с кодами

В AIS предусмотрены операции:

### Нанесение

`EMITTED → APPLIED`

### Ввод в оборот

`APPLIED → IN_CIRCULATION`

### Вывод из оборота

`IN_CIRCULATION → WITHDRAWN`

Для вывода из оборота предусмотрены причины:

- Sale;
- Disposal;
- Defect;
- Loss;
- Return;
- Other.

---

## Агрегация

AIS поддерживает создание агрегации:

- SSCC;
- список кодов маркировки;
- статус агрегации;
- дата создания.

В агрегацию можно включать коды, находящиеся в статусе `IN_CIRCULATION`.

Предусмотрена разагрегация.

---

## История

Для кодов сохраняется история изменения статусов.

История содержит:

- код;
- операцию;
- предыдущий статус;
- новый статус;
- участника;
- документ;
- дату и время операции.

Это позволяет проследить жизненный цикл конкретного кода.

# Текшер – проверка DataMatrix

В каталоге `scanner` находится отдельное React-приложение.

### Возможности

- сканирование DataMatrix камерой смартфона;
- выбор камеры;
- сканирование фотографии;
- ручной ввод содержимого DataMatrix;
- разбор GS1 AI 01;
- получение GTIN;
- разбор GS1 AI 21;
- получение серийного номера;
- проверка кода в AIS;
- отображение статуса кода;
- отображение данных учебника;
- отображение владельца;
- отображение истории операций.

### Как работает проверка

`Камера → DataMatrix → GS1 Parser → GTIN + Serial → AIS API → информация о коде`

Для публичной проверки авторизация пользователя AIS не требуется.

API проверки:

`GET /api/marking-codes/lookup?gtin=...&serial=...`

### Автоматическое обновление статуса

После успешной проверки React продолжает обращаться к AIS и автоматически обновляет данные кода примерно каждые 2 секунды.

Поэтому если код был:

`EMITTED`

а затем в AIS его перевели в:

`APPLIED`

пользователю не требуется обновлять страницу или повторно сканировать код.

## Запуск проекта

### 1. Backend AIS

```bash
cd backend
mvn spring-boot:run
```

Backend:

`http://localhost:8080`

### 2. Сканер DataMatrix

В отдельном терминале:

```bash
cd scanner
npm install
npm run dev
```

Сканер:

`http://localhost:5173`

Если сканер открывается на смартфоне по локальной сети, необходимо использовать IP-адрес Mac вместо `localhost`, например:

`http://192.168.1.100:5173`

Backend при этом должен быть запущен на Mac на порту `8080`.
